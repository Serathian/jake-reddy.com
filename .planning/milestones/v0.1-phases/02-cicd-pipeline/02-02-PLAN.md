  <name>Task 1: Create release workflow with Docker publishing and GitHub releases</name>
  <files>.github/workflows/release.yml</files>
  <action>
Create new release.yml workflow based on RESEARCH.md "Complete Release Workflow" pattern:

**Trigger:** Tag pushes matching `v*.*.*` pattern (semver tags only)

**Job: docker-release**
- runs-on: ubuntu-latest
- permissions:
  - contents: write (for GitHub releases)
  - packages: write (for GHCR push)
  - attestations: write (for build provenance)
  - id-token: write (for OIDC)

**Steps (in order):**
1. Checkout repository (actions/checkout@v4)
2. Log in to GHCR (docker/login-action@v3)
   - registry: ghcr.io
   - username: ${{ github.actor }}
   - password: ${{ secrets.GITHUB_TOKEN }}
3. Extract Docker metadata (docker/metadata-action@v5)
   - Generate semver tags: {{version}}, {{major}}.{{minor}}, {{major}}
   - Disable major tag for v0.x.x versions (unstable)
4. Build and push Docker image (docker/build-push-action@v6)
   - context: . (current directory)
   - push: true
   - tags: from metadata step
   - labels: from metadata step
5. Generate artifact attestation (actions/attest-build-provenance@v3)
   - subject-name: full image name
   - subject-digest: from push step
   - push-to-registry: true
6. Create GitHub Release (softprops/action-gh-release@v2)
   - generate_release_notes: true (automatic changelog)

**Environment variables:**
- REGISTRY: ghcr.io
- IMAGE_NAME: ${{ github.repository }}

Use EXACT workflow structure from RESEARCH.md to avoid permission and authentication issues. The pattern is battle-tested with official GitHub documentation.
  </action>
