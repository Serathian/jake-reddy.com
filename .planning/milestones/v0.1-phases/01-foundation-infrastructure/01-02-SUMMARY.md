## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed Vitest configuration to use plain defineConfig**
- **Found during:** Task 4
- **Issue:** Plan specified using `getViteConfig()` from 'astro/config' which caused runtime error: `Cannot read properties of undefined (reading 'ssr')`. This error occurs because Vitest initialization happens before Astro's config is fully loaded.
- **Fix:** Changed vitest.config.ts to use `defineConfig` from 'vitest/config' directly instead of wrapping with getViteConfig. This provides direct Vitest configuration without Astro dependencies.
- **Files modified:** vitest.config.ts
- **Commit:** b8197e7
- **Impact:** Vitest now starts successfully and runs tests. No loss of functionality - unit tests don't require Astro-specific features.

**2. [Rule 2 - Missing Critical] Added ESLint override for src/env.d.ts**
- **Found during:** Task 2
- **Issue:** ESLint flagged `/// <reference types="../.astro/types.d.ts" />` in src/env.d.ts as error. This triple-slash-reference is auto-generated by Astro and required for proper TypeScript type resolution.
- **Fix:** Added override rule in .eslintrc.json to disable `@typescript-eslint/triple-slash-reference` specifically for src/env.d.ts file pattern.
- **Files modified:** .eslintrc.json
- **Commit:** 5fbc389
- **Impact:** ESLint now passes without errors while preserving Astro's required type references.

**3. [Rule 2 - Missing Critical] Added .prettierignore file**
- **Found during:** Task 3
- **Issue:** Initial Prettier run attempted to format .planning/, .opencode/, and design-system/ directories which contain markdown with special syntax and configuration files that shouldn't be formatted. This caused syntax errors.
- **Fix:** Created .prettierignore to exclude: .planning/, .opencode/, design-system/, dist/, node_modules/, .astro/
- **Files created:** .prettierignore
- **Commit:** ebce541
- **Impact:** Prettier now only formats source code files, avoiding corruption of documentation and tooling configuration.

## Key Decisions Made

1. **Use plain Vitest defineConfig instead of Astro's getViteConfig**
   - **Rationale:** getViteConfig caused initialization errors due to SSR config dependencies
   - **Trade-off:** Unit tests run in isolation from Astro but don't need Astro features
   - **Future impact:** Component tests may need different configuration approach

2. **Allow triple-slash-reference in src/env.d.ts**
   - **Rationale:** Required by Astro framework for type generation
   - **Trade-off:** ESLint rule disabled for one specific file only
   - **Future impact:** Other files still subject to triple-slash-reference rule

3. **Exclude planning and tooling directories from Prettier**
   - **Rationale:** These directories contain special markdown syntax and configs
   - **Trade-off:** Manual formatting if needed in excluded directories
   - **Future impact:** Must update .prettierignore if new special directories added
