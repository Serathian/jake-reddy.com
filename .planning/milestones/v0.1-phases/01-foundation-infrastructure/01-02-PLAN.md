<task type="auto">
  <name>Task 2: Configure ESLint for Astro and TypeScript</name>
  <files>.eslintrc.json</files>
  <action>
    Create `.eslintrc.json` with Astro and TypeScript support:
    
    1. Create `.eslintrc.json` with this configuration:
       ```json
       {
         "extends": [
           "eslint:recommended",
           "plugin:@typescript-eslint/recommended",
           "plugin:astro/recommended"
         ],
         "parser": "@typescript-eslint/parser",
         "parserOptions": {
           "ecmaVersion": "latest",
           "sourceType": "module"
         },
         "env": {
           "node": true,
           "es2022": true,
           "browser": true
         },
         "overrides": [
           {
             "files": ["*.astro"],
             "parser": "astro-eslint-parser",
             "parserOptions": {
               "parser": "@typescript-eslint/parser",
               "extraFileExtensions": [".astro"]
             }
           }
         ],
         "rules": {
           "@typescript-eslint/no-unused-vars": ["warn", { "argsIgnorePattern": "^_" }],
           "@typescript-eslint/no-explicit-any": "warn"
         }
       }
       ```
    
    2. Test ESLint configuration:
       ```bash
       npm run lint
       ```
       
       Expected: Lints all files, may show warnings but should not error on configuration.
    
    **Why this config:**
    - `plugin:astro/recommended`: Official Astro ESLint rules (per research)
    - Overrides section: Uses `astro-eslint-parser` for .astro files specifically
    - TypeScript parser for .ts/.js files
    - Warn on unused vars/any (not error - allows iterative development)
    
    **Don't:**
    - Don't use flat config format (eslint.config.js) - that's ESLint 9.x
    - Don't set `no-unused-vars` to "error" (too strict during development)

<task type="auto">
  <name>Task 4: Configure Vitest with Astro integration</name>
  <files>vitest.config.ts, src/test/example.test.ts</files>
  <action>
    Create Vitest configuration using Astro's `getViteConfig()` helper and add example test:
    
    1. Create `vitest.config.ts` at project root:
       ```typescript
       /// <reference types="vitest/config" />
       import { getViteConfig } from 'astro/config';
       
       export default getViteConfig({
         test: {
           globals: true,
           environment: 'node',
         },
       });
       ```
       
       **Why `getViteConfig()`:** Ensures test environment matches build environment (per research: Pattern 5, Pitfall 7). Without this, import aliases and transforms won't work in tests.
    
    2. Create `src/test/` directory:
       ```bash
       mkdir -p src/test
       ```
    
    3. Create `src/test/example.test.ts` with basic test:
       ```typescript
       import { describe, it, expect } from 'vitest';
       
       describe('Example Test Suite', () => {
         it('should pass basic assertion', () => {
           expect(1 + 1).toBe(2);
         });
       
         it('should handle string operations', () => {
           const siteName = 'jake-reddy.com';
           expect(siteName).toContain('jake');
           expect(siteName.length).toBeGreaterThan(0);
         });
       
         it('should validate TypeScript types', () => {
           const config: { site: string; output: string } = {
             site: 'https://jake-reddy.com',
             output: 'static',
           };
           expect(config.site).toBe('https://jake-reddy.com');
           expect(config.output).toBe('static');
         });
       });
       ```
       
       **Purpose:** Verifies Vitest is working correctly. Tests TypeScript support, basic assertions, and globals configuration.
    
    4. Run tests:
       ```bash
       npm test -- --run
       ```
       
       Expected: All 3 tests pass.
    
    **Don't:**
    - Don't use `defineConfig` from 'vitest/config' (per research: misses Astro settings)
    - Don't use `import { test } from 'vitest'` if `globals: true` is set (inconsistent)
  </action>
