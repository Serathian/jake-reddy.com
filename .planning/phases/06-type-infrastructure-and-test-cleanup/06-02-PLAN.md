<task type="auto">
  <name>Task 1: Migrate Vitest config to astro/config</name>
  <files>vitest.config.ts</files>
  <action>
Update `vitest.config.ts` to use Astro's official `getViteConfig()` helper instead of `defineConfig()` from vitest/config.

**Changes required:**
1. Add triple-slash reference directive at top: `/// <reference types="vitest/config" />`
2. Change import from `import { defineConfig } from 'vitest/config'` to `import { getViteConfig } from 'astro/config'`
3. Change export from `defineConfig({...})` to `getViteConfig({...})`
4. Keep existing test configuration unchanged: `globals: true`, `environment: 'node'`

**Why this migration:**
- Official Astro recommendation as of v4.8+ (see RESEARCH.md Pattern 2)
- Ensures Vitest inherits Astro's Vite configuration (prevents SSR errors)
- Enables future component testing via Container API (Astro 4.9+)
- Triple-slash reference ensures TypeScript recognizes Vitest config types

**What to avoid:**
- Do NOT use `getViteConfig` from `@astrojs/vite-plugin-astro` (deprecated pattern)
- Do NOT change existing test config values (globals, environment) — only change the config helper
- Do NOT remove the triple-slash reference (TypeScript needs it for Vitest-specific properties)

**Reference:** See RESEARCH.md Pattern 2 and official example at https://github.com/withastro/astro/tree/main/examples/with-vitest

<task type="auto">
  <name>Task 2: Add --run flag to test script and exclude .astro/ from Docker</name>
  <files>package.json, .dockerignore</files>
  <action>
Update `package.json` test script and `.dockerignore` for production readiness.

**package.json changes:**
- Update `"test": "vitest"` to `"test": "vitest --run"`
- Keep `"test:ui": "vitest --ui"` unchanged (watch mode for development)

**Why --run flag:**
- Prevents watch mode in non-TTY environments (CI pipelines)
- Eliminates hanging test processes in GitHub Actions
- Vitest auto-detects CI but explicit flag is more reliable
- Single run mode exits after test completion (CI-safe)

**.dockerignore changes:**
- Add `.astro/` on new line after `.github` entry
- This excludes Astro's build cache directory from Docker images

**Why exclude .astro/:**
- `.astro/` contains Vite cache, type generation, and build artifacts
- Build cache is regenerated on each Docker build (not portable)
- Including cache bloats Docker images by 10-50MB unnecessarily
- Official Docker best practice: exclude build caches from images

**What to avoid:**
- Do NOT remove the separate `test:ui` script (developers need watch mode)
- Do NOT add `.astro` without trailing slash (less explicit for directories)
- Do NOT use wildcard patterns like `**/.astro/` (simple `.astro/` is sufficient)

**Reference:** See RESEARCH.md Pattern 3 and Pattern 4 for verified configurations.
